## Findings (most severe first; all non-blocking)

1. **Low-Medium (proven): equipment status badge hidden at phone width.**
   - **Evidence:** at 390x844, `#status-badge` at [8,306, 251x27] and `#orient` at [0,306, 381x38]; `elementFromPoint` on the badge returns `#orient`. Both absolutely positioned at `top:8px`, `z-index:3` (`artifacts/prototypes/p03-qc-model/css/p03.css:38,40`). At 1366 the orientation note also covers the "synthetic" tag.
   - **Consequence:** with a part selected, the info panel only shows status at equipment level (`js/app.mjs:266-267`), so on a phone the selected crane's operational status is not visible anywhere.
   - **Fix:** stack or hide the orientation note on narrow viewports so the badge is always visible. Carry into P10.
2. **Low (proven): P03 viewer has no loading state.**
   - **Evidence:** `viewerState='loading'` (`js/app.mjs:22`) never shown; no skeleton in `index.html`. UX_SPEC line 108 and brief s6 require a viewer skeleton/status.
   - **Consequence:** viewport blank until the GLB parses; tree usable meanwhile.
   - **Fix:** add an `aria-busy` "Loading model…" overlay.
3. **Low (proven): labels clipped at viewport edges.**
   - **Evidence:** `_layoutLabels` (`js/viewer.mjs:378`) checks only the anchor point, not the label box. At 1920, "Main hoist reducer (SEW ML3PSF130E)" cut at the left in the main-01 view; at 1366 side view, "Trolley and operator cab…" and "Headblock and spread…" cut on the right.
   - **Fix:** clamp each label box inside the viewport, or skip it.
4. **Low / advisory for P06 and P10 (prototype shortcut, not a live defect).** `artifacts/prototypes/p03-qc-model/js/data.mjs`:
   - **Mechanism tree** derived from model nodes (lines 13-17), so the tree is decided by what geometry exists (e.g. 014 and 064 unreachable in P03).
   - **Position IDs** derived from manifest array order (`++n`, lines 18-22), so README deep links like `part=pp-q01-041` would move if node order changed.
   - **History is safe:** jobs resolve through semantic keys (lines 44-46); the v2 binding check keeps the v1 IDs.
   - **Fix:** in production, take applicability from Admin-confirmed data and position IDs from the database.
5. **Low (proven, P02): fleet error state shows a misleading refresh time.**
   - **Evidence:** in `data=error` the page shows "Data refreshed 20:46:47" next to "The fleet could not be loaded" (`artifacts/prototypes/p02-ui/js/views-fleet.js:11-13` uses `lastGoodAt` even with no data).
   - **Fix:** say there was no successful refresh, or show the failed attempt's time.
6. **Low (presentation, for U1): tell the user which QC view to judge.**
   - P02 QC detail still shows its placeholder schematic; 11 of its 32 fixture keys are not in the v1 model (e.g. `hoist.drive.gearbox.a`, `gantry.bogie.waterside.a`). Its header says "Model: CICT-J526A-STS (verified)" while P03 says draft and not assigned.
   - Mitigated: placeholder labelled "not the P03 model"; the "Open 3D model (P03)" link reports missing keys instead of guessing.
   - **Model fidelity is judged on the P03 page.**
   - Visual approximations to point out: the A-frame stair renders as disconnected staggered bars about 2 m outboard of the drawn stair (`comparison/end-ws-pair.png`); boom lacing pattern differs from the GA plan (`comparison/top-overlay.png`, already approximation 9).
