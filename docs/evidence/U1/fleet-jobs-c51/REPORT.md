# U1-C51 Project and fleet-wide special jobs

24 October 2026. Added Project alongside Repair and Replacement. The creation form now offers EQ type and Equipment, with equipment filtered by type and an All [type] equipment choice. Changing type clears the previous equipment/component target. A single equipment retains its mechanism/submechanism/part scope; All equipment uses whole-equipment scope. The form gives a short explanation of shared progress/completion and automatic inclusion of later equipment.

The user confirmed **one shared progress and completion record** and **inclusion of equipment added later**. A type-wide job therefore has one identity and one Jobs-list/count/export entry. Each active equipment of that type displays the same current-state special job and links to its shared detail. Adding equipment later includes existing open and completed shared jobs immediately. A later equipment sees the shared completed status without a new equipment-specific installation or completion event. Retired equipment is excluded from the live type scope; open shared work prevents member retirement. Shared history and actual position/installations remain retained.

Progress/date/note, work status, Show, cancellation, completion, reopening and version belong to the one job. Existing creator/role rules remain. Scope is immutable after creation. CurrentSpecial remains a detached current-state projection, with requested-equipment context and type-scope identity, excluding private progress notes/history. Component matching positions are filtered to their actual equipment. Equipment operational status remains separate; an explicit related-status command now accepts a shared job only for relevant equipment.

Project completion permits optional replacement lines; Replacement still needs a committed/new line and Repair takes none. Fleet replacement choices identify each equipment and position. Lines retain their real position owner; all installation/register changes validate against the scope and commit atomically. No replacements are fabricated for untouched or later equipment. API/data contracts describe the nullable single-equipment/type scope and supersede incompatible single-equipment Job composite FKs for later implementation; no production migration is performed.
