## 2 Changes

### U1-C20 EQ Jobs in four tabs
- `views-eqjobs.js`: tabs Special/Projects (`#/eq/jobs/special`), Daily work (CMMS) (`#/eq/jobs/daily`), EQ status, Spare parts condition. Special/Projects holds the manual special jobs, filters and scoped history; Daily work (CMMS) holds the read-only ZMMS daily jobs with "ZMMS data from", default today, earlier days by From/To, Export. Shared filters stay in the URL across the four tabs; the legacy `#/eq/jobs` lands on Special/Projects.
- `panel-tabs.js`: the crane-view Maintenance "Open in Jobs" opens Daily work (CMMS) for the equipment and today (flat view and the P03 3D page share this code).

### U1-C21 Add special job and Add spare part
- "Add special job" in Special/Projects, "Add special job here" in a scoped history, the crane-view Projects/Special tab (whole equipment and any selection, pre-filled) and the equipment header; dialog title "Add special job" (`dialogs.js`, `views-equipment.js`).
- `spares.js` `EQ.spares.add` (simulated `POST /equipment/{id}/spare-parts`, `eq.work`): designation + first condition (Original / Replaced / keep the recorded installation) in one step, history source `registerAdd`, nothing saved on any refusal (403 for Management/FAC Team; 404/409/422 rules of DATA s16.3). Form `EQ.dlg.addSpare` in `views-eqjobs.js` (equipment, main, sub, position, type, expected life, condition, date, description, brand, model, serial, remarks), offered in Spare parts condition and in the crane-view Spare parts tab with the selection pre-filled.
- `access.js`: the `eq.work` row reads "EQ work: special jobs, status correction, add spare parts and update their condition (U1-C21)"; `admin.access` names spare-part types and expected life. No ceiling changed.

### U1-C22 Admin add/adjust in EQ settings
- Mechanism catalogue (`views-admin.js`, `store.js` `addMainDef` / `addSubDef` / `editDef`, `setCatalogActive` for mains): add main (new two-digit code; `10`, `00`, existing codes refused) and sub (main code + one digit, unique, active parent); edit name/description with the previous values in "Catalogue changes"; `061` Spreader / `062` Headblock names locked (409 `approved_name_locked`); `048`/`063` stay reserved; counts show the delivered 16/43 plus "n added by Admin"; a fixtures reset restores the delivered catalogue.
- Main-part positions (`views-admin.js`, `store.js` `addPosition` / `editPosition`): add a draft position to one equipment; edit name/source always, key and mechanism only while draft, kind/unit only before history (409 `position_key_frozen`, `ancestors_frozen`, `history_exists`, `duplicate_semantic_key`); "Position changes" list.
- Specifications (`views-admin.js`, `store.js` `addSpec` / `editSpec` / `resolveParameter` with source and kept earlier values; `views-equipment.js` Technical tab): Admin-entered rows labelled as such; Set/Change/New value on every row, Resolve on conflicts; earlier values shown under the row; drawing definitions refused (409 `source_definition_fixed`).
- Spare parts (`views-admin2.js`, `spares.js` `addType` / `renameType` / `setTypeActive`): add, rename, retire/reactivate types (retired type refused for new designations and additions; registered parts keep it); "Add spare part", per-position "Add with condition" and "Edit entry" (register actions).
